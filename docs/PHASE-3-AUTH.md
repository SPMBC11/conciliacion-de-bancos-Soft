# FASE 3 — Autenticación y administración · FinAgent AI v1

Fecha: 13/11/2026 · Estado: **COMPLETADA**

## 1. Qué se hizo

### Backend

| Área                 | Resultado                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Modelo de datos      | Migración `auth_rbac`: `roles`, `permissions`, `role_permissions`, `organization_members`, `user_sessions`, `invitations`, `password_reset_tokens`. Correos forzados a minúsculas (CHECK) y unicidad de roles de sistema (índice parcial)                                                                                                                                                               |
| Contraseñas          | argon2id; mínimo 12 caracteres; bloqueo de 15 min tras 5 intentos fallidos; tiempo de respuesta igualado cuando el correo no existe                                                                                                                                                                                                                                                                     |
| Sesiones             | Access token JWT (HS256, 15 min) + refresh token opaco **rotativo** (7 días), ambos en cookies `httpOnly; SameSite=Strict` (`Secure` en producción). El refresh solo viaja a `/api/auth`. En BD solo se guarda el hash SHA-256                                                                                                                                                                          |
| Robo de sesión       | Reutilizar un refresh ya rotado **revoca toda la familia** y queda en auditoría. Margen de 30 s para la carrera normal entre pestañas                                                                                                                                                                                                                                                                   |
| Revocación inmediata | Cada solicitud verifica que la sesión siga activa: cerrar sesión, cambiar o restablecer contraseña y “cerrar sesión remota” surten efecto al instante                                                                                                                                                                                                                                                   |
| CSRF                 | Doble envío (cookie legible + cabecera `X-CSRF-Token`) en **todo** método de escritura, incluido el login                                                                                                                                                                                                                                                                                               |
| Límite de velocidad  | 10 solicitudes/min por IP en login, recuperación, invitaciones (configurable); 300/min general                                                                                                                                                                                                                                                                                                          |
| RBAC                 | 21 permisos y 6 roles de sistema definidos en `@finagent/contracts` (fuente única para API y web), sincronizados al arrancar. Roles personalizados por organización. Verificación **siempre en backend** con `@Org('permiso')`                                                                                                                                                                          |
| Anti-escalada        | Nadie otorga permisos que no tiene; solo un Propietario asigna/modifica Propietarios; nadie cambia su propio rol ni se desactiva; la organización nunca queda sin Propietario activo                                                                                                                                                                                                                    |
| Multiorganización    | Cabecera `X-Organization-Id` + membresía activa; respuesta idéntica si la organización no existe o no es miembro (no revela existencia). Recursos de otra organización → 404                                                                                                                                                                                                                            |
| Invitaciones         | Solo registro por invitación: enlace de un solo uso, 7 días, por correo. Una cuenta existente se une a otra organización confirmando su contraseña                                                                                                                                                                                                                                                      |
| Recuperación         | Enlace de 1 hora, un solo uso; misma respuesta exista o no el correo; cierra todas las sesiones                                                                                                                                                                                                                                                                                                         |
| Auditoría            | `AuditService` con contexto de solicitud (usuario, organización, IP, origen UI/API, correlation ID) vía `AsyncLocalStorage`; elimina secretos antes de guardar. Eventos: login (éxito/fallo/bloqueo), logout, reutilización de refresh, recuperación/cambio de contraseña, sesiones, invitaciones, miembros, roles, organizaciones. Consulta `GET /api/audit-logs` filtrable y aislada por organización |
| Arranque             | CLI `npm run bootstrap -w @finagent/api -- --nit … --name … --email …` crea la organización y la invitación del primer Propietario                                                                                                                                                                                                                                                                      |

### Endpoints nuevos

`GET /api/auth/csrf` · `POST /api/auth/login` · `POST /api/auth/refresh` · `POST /api/auth/logout` · `GET /api/auth/me` · `POST /api/auth/forgot-password` · `POST /api/auth/reset-password` · `POST /api/auth/change-password` · `GET /api/auth/invitations/:token` · `POST /api/auth/accept-invitation` · `GET /api/auth/sessions` · `DELETE /api/auth/sessions/:familyId` · `GET/POST /api/organizations` · `GET/PATCH /api/organizations/current` · `GET /api/users` · `POST /api/users/invitations` · `DELETE /api/users/invitations/:id` · `PATCH /api/users/:memberId` · `GET /api/permissions` · `GET/POST /api/roles` · `PATCH /api/roles/:id` · `GET /api/audit-logs`

### Frontend

| Área             | Resultado                                                                                                                                                                                                                                                  |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Páginas públicas | Iniciar sesión, recuperar contraseña, nueva contraseña, aceptar invitación (cuenta nueva o existente)                                                                                                                                                      |
| Protección       | Rutas privadas → `/login?next=…` (solo rutas internas: sin redirección abierta). Pantalla “Sin permiso” si se entra por URL a algo no permitido. Usuario sin organización → puede crear una                                                                |
| Cliente HTTP     | CSRF automático, organización activa en cada solicitud, renovación de sesión transparente (una sola a la vez) y errores en español                                                                                                                         |
| Encabezado       | Selector de organización (si pertenece a varias) y menú de usuario (Preferencias, Seguridad, Cerrar sesión)                                                                                                                                                |
| Menú             | Filtrado por fase **y por permiso**                                                                                                                                                                                                                        |
| Administración   | Usuarios (invitar, cambiar rol, desactivar/reactivar, revocar invitaciones; todo con confirmación), Roles y permisos (matriz agrupada; solo se ofrecen permisos que el usuario tiene), Auditoría (filtros, paginación del servidor, detalle antes/después) |
| Configuración    | Preferencias (perfil y tema), Seguridad (cambio de contraseña, sesiones abiertas con cierre remoto)                                                                                                                                                        |
| Formularios      | React Hook Form + los mismos esquemas Zod del backend                                                                                                                                                                                                      |

## 2. Cómo probarlo

```bash
npm run infra:up && npm run db:migrate
npm run build -w @finagent/domain -w @finagent/contracts && npm run build -w @finagent/api
npm run bootstrap -w @finagent/api -- --nit 900000001-1 --name "Mi Empresa S.A.S." --email yo@empresa.co
npm run dev
```

Abrir el enlace impreso, crear la contraseña y entrar. Los correos (invitaciones, recuperación) llegan a Mailpit: http://localhost:8025.

## 4. Errores encontrados y corregidos durante la fase

- Tras un login correcto la app volvía al login: `queryClient.clear()` eliminaba la consulta de sesión que los componentes observaban. Ahora solo se borran los datos de negocio.
- Tras el login se ignoraba `?next=` (el guardia de páginas públicas redirigía primero al panel).
- La clave de roles con tildes quedaba mal formada (`CUSTOM_TESORERI_A`).

## 5. Decisiones y pendientes

| Tema                           | Detalle                                                                                                                               |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| MFA (TOTP)                     | Planificado; no incluido en v1 por alcance. El modelo de sesión lo admite sin cambios de fondo                                        |
| Permisos por cuenta bancaria   | Se agregan en la Fase 4, cuando existan las cuentas                                                                                   |
| Límite de velocidad en memoria | Por instancia. Con varias instancias de la API se moverá a Redis (Fase 10)                                                            |
| Bloqueo por cuenta             | Revela que la cuenta existe tras 5 fallos (mensaje 429). Se prefirió la claridad para el usuario; se puede cambiar a mensaje genérico |
| Campos de fecha                | Usan el selector nativo del navegador: el formato visible depende del idioma del navegador (dd/mm/aaaa en es-CO)                      |
| Ley 1581                       | Los correos de intentos fallidos quedan en auditoría como registro de seguridad; se documentará en `SECURITY.md`                      |
